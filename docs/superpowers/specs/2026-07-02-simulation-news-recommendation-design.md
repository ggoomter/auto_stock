# 설계: 모의투자 시뮬레이션·당일 뉴스·추천 종목 정상화

- 날짜: 2026-07-02
- 상태: 사용자 승인됨 (구현 계획 작성 전)
- 범위: 실전 자동매매 제외. (1) 가상(paper) 시뮬레이션, (2) 그날의 뉴스 파악, (3) 추천 종목을 실제로 동작하게 만든다.

## 1. 배경

2026-07-02 코드베이스 감사에서 확인된 핵심 문제:

- 펀더멘털 백테스트 전체가 look-ahead bias로 오염 (`fundamental_analysis.py:728-731` — 과거 날짜에 현재 시점 `ticker.info` 재무 사용). 시점별 조회 경로는 `self.dart_client` 속성 버그로 죽은 코드 (`fundamental_analysis.py:711-715`).
- 몬테카를로가 시그널 날짜 정렬 실패로 거래 0건 → 신뢰구간 전부 허수 (`monte_carlo.py:52-53, 124-128`).
- 실전(LIVE) 주문 경로는 존재하지 않는 메서드(`buy_stock/sell_stock`) 호출로 즉시 크래시 (`auto_trading_engine.py:471,477` vs `broker_api.py`). `/trading/start`는 무인증.
- 포지션이 메모리 전역 변수에만 존재 → 재시작 시 소실. DB 없음.
- 뉴스/이벤트 수집은 스케줄러 미기동으로 영구 미작동 (`event_scheduler.py:181`).
- 스크리너는 존재하지 않는 enum 참조로 대형 시장에서 크래시 (`stock_screener.py:328`).
- 프론트 커스텀 전략 차트가 `Math.random()` 가짜 데이터 (`StockChart.tsx:23-140`), 에러 바운더리 전무, 피드백은 전부 `alert()`.

## 2. 확정된 요구사항

- **대상 시장**: 한국 주식(KOSPI/KOSDAQ) 우선. 미국 주식은 기존 수준 유지.
- **시뮬레이션**: 과거 백테스트 신뢰성 수리 + 실시간 모의투자 정상화, 둘 다.
- **뉴스**: 당일 뉴스 자동 수집 + 종목 연결 + 키워드 기반 호재/악재 태그. LLM 요약은 범위 외.
- **추천**: 펀더멘털 스크리닝 + 기술적 시그널 혼합. 종목마다 "왜 추천되는지" 조건별 통과 내역 + 당일 뉴스를 함께 표시.
- **실행 환경**: 서버는 상시 구동이 아님. 기동 시 "오늘치 따라잡기(catch-up)" 방식. DB 영속화 필수.
- **실전 매매**: LIVE 모드는 feature flag로 차단 (403 반환).

## 3. 선택한 접근: 수리 + 최소 신규 (A안)

기존 FastAPI + React 구조 유지. SQLite 추가. 깨진 부분을 수리하면서 3개 기능을 기존 서비스 위에 재구성.

기각한 대안: (B) 시뮬레이션 코어 전면 재작성 — 공수 2배 이상, 중간 산출물 없음. (C) backtrader/vectorbt 채택 — 새 의존성 + 기존 UI 어댑터 재작성 부담, 한국 거래세 등은 결국 직접 구현.

**새 외부 의존성 없음**: DB는 Python 표준 `sqlite3`, 뉴스 수집은 기존 `requests` + `BeautifulSoup`.

### 4.1 DB 스키마 (SQLite)

| 테이블 | 용도 |
|---|---|
| `paper_positions` | 모의투자 포지션: 종목, 수량, 진입가/일시, 전략, open/closed, 청산가/일시/사유 |
| `paper_trades` | 모의투자 체결 이력 (감사 추적) |
| `portfolio_snapshots` | 일별 가상 잔고 평가액 → 수익 곡선 |
| `news_articles` | 발행일, 소스, 제목, URL, 요약, 태그(호재/악재/중립) |
| `news_stock_links` | 뉴스 ↔ 종목 다대다 |
| `recommendations` | 날짜, 종목, 점수, 통과 조건 JSON, 기술 시그널 JSON |
| `job_runs` | 작업명, 대상일, 상태(성공/실패/사유) → 따라잡기 판단 근거 |

### 4.2 따라잡기(catch-up) 흐름

FastAPI lifespan에서 `daily_jobs.py`를 백그라운드 태스크로 실행:

1. `job_runs` 조회 → 오늘 아직 안 돈 작업만 실행 (중복 방지).
2. 순서: 뉴스 수집 → 추천 생성 → 모의투자 정산.
3. 모의투자 정산: 서버가 꺼져 있던 기간은 일봉 데이터로 **보수적으로** 정산. 손절가 터치 시 해당일 종가와 손절가 중 불리한 쪽으로 청산 처리.
4. 장중(09:00~15:30 KST)이면 10분 주기 루프로 모니터링 + 스냅샷 저장.
5. 각 작업은 독립 try/except. 실패는 `job_runs`에 기록하고 다음 작업 진행.

## 5. 기능별 상세

### 5.1 백테스트 신뢰성 수리

- `check_*_criteria_at_date()`가 시점별 재무를 실제로 사용하도록 수정. 한국 주식은 DART 분기보고서에서 **해당 날짜에 이미 공시된 최신 분기**만 사용. `self.dart_client` → `self._dart_client`, `self.ticker.replace()` 타입 버그 수정.
- 재무 데이터 없는 구간은 "무조건 통과"(현행) → **매수 불가**로 변경. 결과에 "펀더멘털 검증 가능 구간" 명시.
- `backtest.py`: 한국 주식 매도 시 증권거래세(0.18%, 설정값 분리) 추가. 부분 익절에도 슬리피지 적용.
- `korean_stock_data.py`: `_enhance_samsung_data()`(삼성전자 하드코딩) 삭제. Lynch 성장률 기본값 0.10 / ROE 대체 로직 삭제.
- 몬테카를로, Chanos 전략: UI/API에서 숨김 처리 (수리는 별도 TODO).

### 5.2 모의투자 정상화

- `/trading/start`에서 `mode=live` → 403 + "실전 모드는 비활성화됨".
- 메모리 포지션(`active_positions` dict) → `paper_positions` 테이블. 재시작 시 open 포지션 복원.
- 평가액·손익을 현재가(yfinance 지연 시세) 기준으로 계산. UI에 "시세 약 15분 지연" 배지.
- 가상 체결: 매수 = 현재가 호가단위 올림 + 슬리피지, 매도 = 내림 (`tick_size.py` 재사용).
- Kelly 사이징(하드코딩 승률 0.5) 제거 → 단순 균등 배분(1/N).

### 5.3 뉴스 수집 + 종목 연결 (`naver_news.py`)

- 소스: 네이버 금융 시장 뉴스 + 종목별 뉴스 페이지. `requests` + `BeautifulSoup`. 기존 `news_crawler.py`(NewsAPI/Selenium)는 미사용.
- 종목 연결: pykrx 전 종목명 사전으로 제목 매칭 (예: "삼성전자" → 005930). 관심·보유·추천 종목 우선.
- 태그: 키워드 사전 기반. 호재(수주·흑자전환·신고가·상향 등) / 악재(적자·소송·하향·유상증자 등) / 중립.
- 주기: 기동 시 catch-up + 장중 30분. 요청 간 1초 딜레이. 실패 시 `job_runs` 기록만, 앱은 정상 동작.

### 5.4 추천 종목 (`recommender.py`)

- 1차: pykrx 시가총액·거래대금 상위 약 300종목 (yfinance `.info` 폭탄 호출 회피).
- 2차: 수리된 `stock_screener.py`(GRAHAM enum 크래시 수정)로 버핏/린치/그레이엄 펀더멘털 평가.
- 3차: `indicators.py`로 당일 기술 시그널 (골든크로스, RSI 반등, 52주 신고가 근접).
- 점수화 + 조건별 통과 내역 JSON 저장. API는 조건 체크리스트 + 당일 관련 뉴스와 함께 반환 (기존 조건 체크 UI 패턴 재사용).
- 추천 화면에 "교육·연구용, 투자 권유 아님" 고지 필수.

## 6. UI 변경 (3개 기능 직결분만)

## 7. 에러 처리 원칙

- 작업 계층: job별 독립 try/except → `job_runs` 기록. UI에 실패 사유 표시.
- 외부 데이터 계층: yfinance/pykrx/네이버/DART 호출은 타임아웃 + 1회 재시도. **조용한 기본값 대체 금지** — "데이터 없음"을 명시적으로 반환.
- API 계층: 500 응답에 내부 예외 문자열 노출 중단, 상세는 로그에만.

## 8. 테스트 전략

- **백테스트 수학 단위 테스트 (최우선)**: 합성 가격 픽스처로 체결가(다음 봉 시가 + 호가단위 + 거래세)·손익·MaxDD assert. **look-ahead 가드**: 재무 공시일 이전 날짜에 그 재무로 매수 판단이 나오면 실패하는 회귀 테스트.
- **뉴스 매칭**: 고정 HTML 픽스처로 종목 매칭·태깅 검증 (네트워크 불필요).
- **모의투자 정산**: "서버 3일 꺼졌다 켜졌을 때 손절 터치 포지션이 보수적으로 청산되는가" 시나리오.
- **구조 정리**: 루트 산재 `test_*.py`는 `tests/legacy/`로 이동. 신규는 `tests/unit/`, `tests/integration/` pytest 체계.
